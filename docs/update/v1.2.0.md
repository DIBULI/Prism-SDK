# Prism SDK v1.2.0

- Add matching Host/RK-local C++ Sensor Board background maintenance APIs and
  job status. Agent/Web remain running; capture must stop. Add version skip,
  force override, SHA-256 staging validation, restart verification and independent
  RK-local IPC. Update headers/libraries together; old 1.2.0 Agent builds lack
  this extension. No Sensor Board firmware change. Runtime API v18 is unchanged;
  the new operations use direct C++ linking. See [maintenance](../guides/firmware-update.md#agent-managed-sensor-board-maintenance).

- Fix premature post-calibration verification: reject zero/backward/impossible
  TIME_SYNC samples and retry reads for up to six seconds. Never use unavailable
  time or a new epoch as a second correction. Deploy the matched Agent, which
  waits for three fresh aligned PPS pairs and rechecks readiness after PHC
  verification. TIME_SET has a minimum 35-second settling timeout in Host and
  RK-local; public signatures/wire layouts stay unchanged. No Sensor Board update
  is required. UTC retention and the separate later time rollback are not fixed.
- Fix Host USB keepalive lifecycle during explicit idle clock calibration.
  `synchronizeSystemTime()` temporarily suppresses heartbeat writes while Agent
  processes the long command, then resumes them on success or exception without
  changing the caller's enable state or interval. This prevents later acquisition
  stopping because the heartbeat worker exited; reopening the client is no longer
  required for this failure. Calibration errors are still reported normally.
  Public APIs, ABI and the capture watchdog are unchanged. RK-local/Web do not
  use this USB worker; the heartbeat fix alone needs no device firmware update. Clock rollback /
  UTC retention is outside this fix. See [time synchronization](../guides/time-sync.md).
- Consolidate SDK documentation into getting-started, reference, feature guides,
  examples and release notes. Merge related GNSS/RTK, TimeSync and LiDAR pages,
  repair navigation, and validate local links/anchors in package checks.
  That earlier documentation-only refresh did not change SDK headers, libraries or ABI.
- Add independent LiDAR hardware query/standby/wake for MID360/MID360S/XT32,
  with identical Host and RK-local C++ methods and a version-1 Windows DLL
  extension. Ordinary capture start/stop is unchanged. All streams must be idle;
  timeout means unconfirmed, not successful standby. See [power controls](../guides/lidar.md#standby-wake).
- Add matching Host USB / RK-local raw dataset list, manifest, bounded chunk read and download APIs. SDK exports original format only; no ROS1/ROS2 bag conversion or ROS offline download API.
- Add 64-bit offsets, chunk CRC32, file-change detection, cancellation and exclusive destination creation. DatasetRuntimeApi v1 is a separate extension; RuntimeApi v18 is unchanged. Requires the refreshed Agent 1.2.0 build.

- Includes a header-only GCC 9/11 compatibility adjustment and numeric-parser regression test, without changing the public interface or binary ABI.
- Update Host and RK-local C++ SDKs together for Agent **1.2.0** and Sensor Board **0.4.27**.
- Add unified CORS read/save and explicit RTK start/stop APIs, with generation-bound GGA consent and timeout/error reporting.
- Add RTK-module versions, control/4G status, current TimeSync modes, GNSS receive diagnostics and observation streams for receiver-native sky/trajectory display.
- Publish current XT32/LiDAR line-field and camera metadata/exposure interfaces.
- Remove the retired Agent `raw/smoothed` navigation interface; read receiver-native results instead.
- Refresh public headers, Linux x64/ARM64 shared/static libraries, ARM64 RK-local archive, macOS ARM64 dylibs and Windows x64 DLL from one source commit.
- Update Chinese/English guides and compile-checked examples, including RTK-module controls.

Compatibility: exact Agent **1.2.0** handshake; wire protocol **1**; Windows Runtime API **18**, RTK-module control extension **1**. Replace all headers/libraries and rebuild. Linux uses the Ubuntu 20.04 ABI baseline; macOS targets Apple Silicon/macOS 13+; Windows targets x64/MSVC 14.x.

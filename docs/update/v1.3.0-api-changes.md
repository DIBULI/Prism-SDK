# 1.2.x → 1.3.0 API 变更与迁移

[中文更新说明](v1.3.0.zh-CN.md) · [English release notes](v1.3.0.md) · [文档目录](../README.zh-CN.md)

对照公开 `v1.2.0` 头文件和 `v1.2.1-pps5ms` 维护版本。本文说明公开 API 与行为变化，
不包含私有实现源码。新增头文件也属于变化范围，不仅是已有文件的修改。

## 必须处理的兼容性变化

| 项目 | 1.2.x | 1.3.0 | 应用迁移要求 |
| --- | --- | --- | --- |
| SDK / 配套 Agent | 1.2.0；PPS 维护版为 1.2.1 | 1.3.0 | 使用匹配的设备软件；不关闭版本检查 |
| `kRuntimeApiVersion` | 18 | 19 | 更新 DLL/库和头文件，重新编译；旧 ABI 不可混用 |
| `DeviceInfo` | 无 `device_model` | 新增 `DeviceModel device_model` | C++ 对象布局变化；不能只替换动态库 |
| DeviceInfo 线协议 | v4，256 字节 | v5，仍 256 字节，同时解析 v4 | 旧 v4 的型号为 `Unknown`，不凭路径/IP 推断 |
| `GnssTimingStatus::pps_min_high_us` 默认值 | v1.2.0 为 20000；PPS 维护版已为 5000 | 5000 | 显示实际查询结果；SDK 不会改变旧固件的脉宽门槛 |

现有公开方法未因本次变更被删除或改名，但这**不等于二进制 ABI 兼容**。
Windows `LoadLibrary` 客户端应按新头文件请求 Runtime API 19，检查返回指针、
`abi_version`、`struct_size` 和编译器兼容性。网络扩展独立为版本 3，
不能将扩展的版本号当作主 Runtime API 的版本号。

## 新增或扩展的公开接口

| 范围 / 头文件 | 新接口 | 使用约束 |
| --- | --- | --- |
| `usb/common.hpp` | `DeviceModel`、`deviceModelName()`、`DeviceInfo::device_model` | 枚举/旧协议可能为 `Unknown`；型号不是实时相机健康状态 |
| `usb/device_info.hpp` | `kDeviceInfoLegacyProtocolVersion=4`；当前版本变为 5 | `parseDeviceInfo()` 接受有效 v4/v5；畸形响应仍失败 |
| `usb/network.hpp` | `NetworkOptions`、`kNetworkCameraMaxFps`、`kWifiCameraMaxFps` | 数字 IP、端口、设备 token、连接超时；明文 TCP，无证书指纹字段 |
| Host `Client` | `openNetwork()`、`openNetworkDevice()`、`isNetwork()`、`networkCameraMaxFps()` | 网络连接显式选择；原 `openFirst()` / `open()` 仍为 USB |
| `usb/network_runtime_api.hpp` | `NetworkRuntimeApi`、`GetNetworkRuntimeApiFunction`、`kNetworkRuntimeApiVersion=3` | 独立入口 `prism_usb_sdk_get_network_api`，与匹配主 API 生命周期配套 |
| Host `Client` | `startProfileVideo(fps)`、`startProfileVideoGpu(fps)` | 显式选择 profile 采集，不隐式替换旧 JPEG 入口 |
| Host `Client` | `startPrism415mVideo()`、`startPrism415mVideo(fps)` | 无参入口保持 1 FPS；显式 2 FPS 需要配套设备能力，不修改持久配置 |
| `usb/profile_video.hpp` | `ProfileImage`、`ProfileImageAssembler::ingest()` | 按路独立、有界组帧；不能等四张齐全才向应用输出 |
| 同上，`prism::capture` | `Raw12Image`、`decodeRaw12()`、`decodeRaw12Zstd()`、`decodeRaw12Rice()`、`raw12Pixel()` | 完整尺寸与 CRC 校验；返回 packed12，保留全部有效位 |
| 同上 | `ProfileGpuFault`、`parseProfileGpuFault()` | 上报具体相机的 GPU 故障，不静默回退或用旧帧填充 |
| RK-local | `CameraExposureCapabilities`、`cameraExposureCapabilities()` | 只读能力查询，不占用采集 Client；不能以型号代替能力判断 |
| RK-local `Client` | `startPrism415mVideo()` | 与 Host 的重载集合不同；不得直接假定存在带 FPS 参数的重载 |

`profile_video.hpp` 是可选头文件，使用解码器时需链接 Zstandard。
`usb_sdk.hpp` 的旧 JPEG 使用方式不因此强制引入 Zstandard。

平台边界：Host `Client` 的新 profile 启动方法是直接 C++ 接口，并未追加到 Windows
主 RuntimeApi 19 函数表。Windows 动态加载调用者不能自行假定存在同名函数指针；
网络通过独立 v3 扩展接入，完整公开函数表以 `runtime_api.hpp` 为准。

### 与早期 TLS 开发版的差异

按当前要求，网络改为明文 `PRISM-NET/3`，不是 `PRISM-NET/2` TLS。
`NetworkOptions::certificate_sha256` 已移除，网络扩展从 2 升为 3；拒绝请求旧扩展版本。
更新 SDK、设备网关和应用，不可只替换 DLL。鉴权 token 保留，但无法抵御网络监听或篡改，
只用于可信局域网/热点，不开放到公网。无自动 TLS/明文回退。
Linux 的 libcrypto 仍用于升级包 SHA-256 校验，不用于网络加密；网络不再依赖 libssl。

## 签名不变，但需要注意的行为

- `Client::readFrame(timeout_ms)`：普通 USB 读超时保留已收到的未完成帧，后续读取继续组帧。
  超时本身不等于丢数据；检查序号、完整性和设备错误。应用应串行调用同一 Client 的读取/命令，
  不因底层异步接收而自行并发访问 Client；状态不明的 I/O 错误需要关闭连接。
- `startVideo1280x1024(fps)`：仍是原 JPEG 入口。网络会话有线最多 20 FPS、Wi-Fi/未知链路
  最多 10 FPS；设备自身更低的上限仍有效。`fps=0` 使用已保存默认值再限速，不改持久参数。
- `stopVideo()` / `stopImu()`：仍停止共享相机/IMU 采集，不因网络接入而变成独立停止。
- 既有升级 API：新增对 format v2 完整应用包的支持，不要求应用换一个升级方法。
  是否可升级必须由设备能力预检决定；仅换 Host SDK 不能给旧设备补上完整升级器。
  见[完整升级包与旧 format v1 的区别](../guides/firmware-update.md)。
- 型号缓存、UART DMA、PTP 时标策略是设备端能力；安装 SDK 不自动更新这些配置或固件。
- 本次 SDK 同步不更改 ROS node 的缺失告警策略，也不重新发布 ROS adapter。

## 迁移示例

### 1. 显示型号，不用 USB 名称猜测

```cpp
const auto info = client.deviceInfo();
const char* model = prism::deviceModelName(info.device_model);
// Unknown 必须按未知显示；不要把它当作某个默认产品。
```

### 2. 保留原 USB 接口，按需新增网络入口

```cpp
// 旧 USB 方式保持有效。
auto usb = prism::Client::openFirst();
// 网络方式使用独立 Client，并由可信配对渠道提供凭据。
// prism::NetworkOptions options = ...;
// auto network = prism::Client::openNetwork(options);
// const auto cap = network.networkCameraMaxFps();
```

以上只是入口对照，不能让两个控制者同时占用同一设备。
可运行的[网络查询示例](../../examples/network_connect.cpp)从 stdin 读取一行 token，
不将凭据放进命令行、URL、日志或普通配置文件。

### 3. RAW12 不能交给旧 JPEG 解码器

```cpp
#include <prism/usb/profile_video.hpp>
// image 是 ProfileImageAssembler 已完成的一张 ProfileImage。
const auto raw = prism::capture::decodeRaw12(image.encoded, image.format);
const auto first_pixel = prism::capture::raw12Pixel(raw, 0); // 0..4095
// raw.packed：两个像素/三个字节；不是 uint16_t 数组。
```

不要丢弃低 4 位，或把 CRC 失败转换为“正常空图”。`timing_mode==3` 的源时间戳不代表
已同步曝光/UTC。完整示例见 [RAW12 解码与合成自测](../../examples/profile_raw12_decode.cpp)。

## 更新清单

1. 同时更新 `include/`、本机架构运行库及 CMake 配置；ROS 安装前缀也须一致。
2. Windows 应用同步改为主 Runtime API 19；按需检查网络扩展 3。重新编译所有相关消费者。
3. Linux 静态链接补齐 libusb、OpenSSL Crypto、Threads；RAW12 解码额外链接 Zstandard。
4. 检查版本/型号未知值、格式分支、超时与真实缺失、CRC/故障事件的处理。
5. 先运行包自检和示例，再在匹配设备版本上做业务验证。离线示例通过不等于设备性能验收。

English summary: update headers and binaries together and rebuild consumers. The main
Runtime API changes from 18 to 19 due to `DeviceInfo` layout changes. Network extension
v3 is separate and uses plaintext TCP, replacing the earlier TLS development transport.
Existing USB/JPEG entry points remain; network and independent RAW12
capture are explicit opt-ins. The PPS maintenance branch already used a 5 ms default.

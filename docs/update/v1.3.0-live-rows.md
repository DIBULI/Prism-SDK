# 1.3.0 live exposure and matched Viewer update

For the current native-controller 415M firmware, use the
[native row/gain API](v1.3.0-native-camera-control.md) instead. This older
live-row interface is retained for compatible firmware, not silently removed
or used as a fallback for the new controller.

This revision retains Host Runtime ABI 19 and uses plaintext Network ABI 4. Replace
headers and all platform libraries together; an older library with the same
1.3.0 version string does not provide the new APIs.

- Host `Client::beginLiveExposureRows(mask, rows)`, `finishLiveExposureRows(frame,
  applied)` and `liveExposureRowsPending()` support 415M integer rows (3–4096).
  There is one outstanding request per connection. Continue reading frames,
  decoding/recording, video acknowledgements and IMU handling while it applies.
  Pass every received frame to `finishLiveExposureRows`; matching stream sequence
  numbers are not command replies. No STOP/START or transition-frame suppression.
- A timeout is unconfirmed, not proof of failure. Do not automatically retry.
  A late matching response can finish the outstanding request. Malformed replies
  or ambiguous writes require explicit connection recovery, not replay.
- `profile_runtime_api.hpp` exports `prism_usb_sdk_get_profile_api(1)` for dynamic
  consumers including Windows: 415M/mixed capture and the live-row methods above.
  The core RuntimeApi table layout is unchanged. Reject a missing extension.
- RK-local adds matching `beginLiveExposureRows`, `finishLiveExposureRows` and
  pending-state access; original camera/IMU frames must continue through its
  intact raw receive queue. See the declarations for exact signatures.
- USB synchronous command replies no longer consume deferred stream data while
  waiting for the matching control response; startup/tail packets are retained.

Use Agent 1.3.0 and the matching model-specific Sensor Board 0.5.0 package.
SDK installation alone does not update device firmware. Network is unencrypted
PRISM-NET/4 with the Web admin password as token; use a trusted network. No TLS fallback.

Offline mocked transport, decoder and runtime-extension checks are distinct
from physical-device endurance or optical-quality acceptance.

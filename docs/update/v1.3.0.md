# Prism SDK 1.3.0

Latest refresh (2026-11-03): native RAW8, canonical model names 415RSV0,
413GSV0 and 21315V0, and matched Windows/macOS/Linux x64/ARM64 libraries.
Wire model IDs and Runtime API 19 remain unchanged. Replace headers and libraries
together; this refresh rebuilds the binaries as well as public interfaces.
See [shared trigger groups](v1.3.0-trigger-groups.md).

[API changes and migration from 1.2.x](v1.3.0-api-changes.md) (Chinese tables with English summary).

Use matching SDK / Agent **1.3.0** and model-specific Sensor Board firmware (**0.5.2** for 415RSV0).
Other model names do not imply a newly qualified firmware package. Replace headers and libraries together and rebuild applications.
Runtime API is **19**, because `DeviceInfo` now includes a device-model field;
the independent network extension is version **4**, and the profile/live-row
extension is version **1**. This replaces the earlier v1.3.0 revision as requested;
do not mix older same-version headers or libraries.

The earlier missing-camera revision updates JPEG assembly headers to use each validated
frame's advertised camera membership. Absent slots remain empty, healthy cameras
continue, corrupt/incomplete advertised images retain diagnostics, and each frame
returns one ACK. Host and both ROS header trees match; the current refresh also rebuilds every platform runtime, without changing ABI 19. The previous network camera/IMU examples are retained. Missing-lane
support requires matching device firmware; this is not legacy-protocol emulation
or a new physical-device qualification.

See [continuous exposure rows](v1.3.0-live-rows.md) and
[Web-password network authentication](v1.3.0-network-web-password.md).

The current revision adds [native row/gain controls and common-trigger timing](v1.3.0-native-camera-control.md),
including CameraControl Runtime API 1, separate AE/AGC, gain/exposure bounds,
idle staging and asynchronous in-capture updates. The legacy exposure API is
retained; it is not the new 415RSV0 controller's fallback.

- Query the device model without inferring it from USB paths, names or IPs.
  Older DeviceInfo v4 replies map to `Unknown`; malformed replies remain errors.
- Bounded asynchronous USB reads retain partial packets across ordinary read
  timeouts and preserve framing and integrity checks.
- Plain TCP connections use the same Client API (trusted LAN/hotspot only; token
  and data are not encrypted). Update the device gateway and consumers together.
  Network capture
  limits are negotiated per session; they do not change saved camera settings.
- Independent native RAW8 assembly and PRG8 decoding preserve each sensor byte
  (0–255) with encoded/decoded integrity checks as defined by each format.
- Complete application update packages can update Agent, Web and network services
  on devices with the matching full updater. Unsupported devices are rejected
  before writes; no automatic legacy bootstrap is provided.
- Supports the current 415RSV0 image envelopes for preview, recording and replay,
  while retaining older RAW8 format support. Update applications with this SDK.
- Device recording can warn and discard the oldest queued camera image when its
  bounded camera queue fills. Recorded drop counts distinguish completion from
  a recording with every received frame retained; IMU accounting is independent.
- RK-local headers and ARM64 library are rebuilt from the same SDK revision.

See [integration requirements and examples](../guides/network-raw.md) and
[update semantics](../guides/firmware-update.md). Source-build/package tests are
not a new physical-device qualification; this SDK update does not reconfigure,
flash or start any device. IMU hardware DMA and PTP clock policy require their
matching device software and are not installed by the Host SDK.
